# Implementation Plan: Results PDF Download

**Branch**: `006-results-pdf-download` | **Date**: 2026-05-25 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/006-results-pdf-download/spec.md`

## Summary

Add a server-rendered "Download PDF" capability to the results page. Two buttons (top + end of report) trigger `GET /api/results/[resultId]/pdf`, which reads the session from Supabase via the service-role client and streams a designed, paginated PDF report built with `@react-pdf/renderer`. The PDF is a deliberately separate visual layout from the on-screen results (light theme for print, paginated sections, header/footer per page) so the output reads as a professional assessment report rather than a screenshot of a web page. Downloads emit a `pdf_downloaded` event to `assessment_events` for admin-dashboard surfacing. Closes v1 launch deliverable **D-2** and resolves risk **R-4**.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 20+
**Primary Dependencies**: Next.js 14 (App Router), `@react-pdf/renderer` (NEW — ~600 KB gzipped, pure JS), `@supabase/supabase-js` (existing service-role client)
**Storage**: Supabase Postgres — read `assessment_sessions` row by resultId via service-role; write `pdf_downloaded` events to `assessment_events`
**Testing**: Vitest (unit + structural snapshot of PDF doc), manual cross-viewer print test (Preview, Adobe, Chrome built-in, mobile Safari Quick Look)
**Target Platform**: Vercel — Node.js runtime (NOT Edge — `@react-pdf/renderer` requires Node APIs)
**Project Type**: Web application (Next.js)
**Performance Goals**: PDF generation < 3s at p95 (cold-cold), download initiates within 500 ms of button click
**Constraints**: PDF text must be selectable (no rasterised content), radar chart must render as inline SVG (not PNG), section breaks must not split charts/stat-cards/paragraphs, rate-limited to 30 req/IP/min
**Scale/Scope**: 1 API route, 1 button component (used in 2 places), ~5 PDF component files, 1 Supabase migration, ~3–5 pages per generated PDF

**Structure Decision**: PDF components are isolated in `src/components/results/pdf/` to make the boundary explicit — these are `@react-pdf/renderer` primitives (`<Page>`, `<View>`, `<Text>`), not DOM React components, and cannot be mixed with the on-screen results UI. ## Implementation Phases

### Phase A: Setup

Land the dependency, the Supabase migration, and the service-role plumbing PDF will reuse.

- Install `@react-pdf/renderer`
- Create migration `<ts>_pdf_downloaded_event.sql` — adds `'pdf_downloaded'` to the `event_type` CHECK constraint on `assessment_events` (the existing `assessment_events_event_type_check` must be dropped + recreated with the new value)
- Verify `src/lib/supabase/service.ts` is usable from this new route path (no Vercel function bundling surprises)

### Phase B: PDF document layout

Build the visual artefact bottom-up so each piece is independently testable.

- `RadarSvg.tsx` — pure SVG radar component (8 axes, gridlines, polygon fill from 8 element scores). No external dep — straight `<Svg>`, `<Polygon>`, `<Line>`, `<Text>` from `@react-pdf/renderer`.
- `CoverPage.tsx` — logo (embedded as base64-or-static SVG), title, user's first name, completion date in "DD MMMM YYYY" (default per spec Q-05).
- `ScoresPage.tsx` — radar chart + 3 summary stat blocks + 8-row element breakdown.
- `ArchetypePage.tsx` — archetype name, message, CTA tier text with clickable link.
- `ReportDocument.tsx` — composes all three pages into a `<Document>` with shared `<Page>` props (size: A4, padding) and a footer (page number `X / N`, first name, "Worship Wheel Assessment").
- `styles.ts` — `StyleSheet.create()` with brand colours pulled from `src/tokens/` and Montserrat font registration via `Font.register()`.
- Unit test: snapshot/structural assertion that `ReportDocument` rendered with a fixture produces a non-empty buffer and contains expected page count.

### Phase C: API route

Wire the endpoint that browsers hit.

- `src/app/api/results/[resultId]/pdf/route.ts` — `GET` handler:
  1. Validate `resultId` param matches UUID v4 regex → 400 if not
  2. Apply rate limit (30/min/IP) using the same shape as `/api/submit` (in-memory map for v1; cron evict if needed)
  3. Read row via `createServiceClient()` from `src/lib/supabase/service.ts` → 404 if not found
  4. Shape row → `PdfData` via `src/lib/pdf/data.ts`
  5. `renderToStream(<ReportDocument data={pdfData} />)` → stream response
  6. Headers: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="worship-wheel-{firstNameSlug}-{YYYY-MM-DD}.pdf"`, `Cache-Control: private, max-age=300`
- Wrap errors → 500 with brief message; log full error server-side.

### Phase D: UI integration

Hook the buttons into the results page.

- `DownloadPdfButton.tsx` — accepts `resultId`, `firstName`, `placement: 'top' | 'bottom'`. On click:
  1. Set local `isLoading` state, disable button
  2. Fetch `/api/results/{resultId}/pdf` as a blob
  3. Create blob URL → trigger `<a download>` click → revoke URL
  4. On success → fire-and-forget `logPdfDownloaded({resultId, anonSessionId, placement})`
  5. On error → show toast / inline error message, restore button
- `src/app/results/page.tsx` — render `<DownloadPdfButton placement="top">` near the page heading and `<DownloadPdfButton placement="bottom">` after the CTA section.

### Phase E: Tracking

Log the download so it shows up on the admin dashboard.

- `src/lib/events/pdf-downloaded.ts` — function `logPdfDownloaded({ resultId, anonSessionId, placement })` that inserts into `assessment_events`:
  ```
  { event_type: 'pdf_downloaded', anon_session_id, client_ts: new Date().toISOString() }
  ```
  Uses the public anon client (the existing `assessment_events_insert_public` policy allows this — same path as the existing event tracking).
- Verify the admin Outcomes view picks up the new event type. If it filters explicitly to known types, add `'pdf_downloaded'` to the allow-list (likely in `src/lib/admin/outcomes-data.ts` or similar).

### Phase F: QA + Charl review

The final mile that makes the output actually professional.

- Manual print test: print the generated PDF on A4. Confirm no section/chart/paragraph cuts.
- Cross-viewer test: open in Preview (macOS), Adobe Reader, Chrome built-in viewer, mobile Safari Quick Look. Confirm no rendering regressions.
- Append entries to `project-management/v1-launch/qa-log.md`.
- Submit to Charl for design review (C-3 deliverable).
